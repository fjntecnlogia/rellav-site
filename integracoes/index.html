Como a integração funciona

Uma camada de sincronização inteligente que conecta o app móvel dos seus vendedores diretamente ao coração do seu sistema de gestão.

01
📱

App do Vendedor

O vendedor usa o Rellav no celular para registrar pedidos, consultar estoque e cadastrar clientes mesmo offline.

02
⚡

Rellav Sync Engine

Nosso motor de sincronização valida, transforma e roteia cada operação para o ERP no formato correto via API.

03
🏢

ERP da Empresa

Os dados chegam ao seu ERP como se tivessem sido lançados diretamente no sistema — sem duplicidade, sem erro.

04
📊

Gestão em Tempo Real

Relatórios, comissões e metas são atualizados automaticamente. Seu gestor vê tudo em tempo real no painel.

Detalhes técnicos

Documentação técnica para seu time de TI avaliar a integração. Todos os conectores seguem os mesmos padrões de segurança e arquitetura.

🔐

Autenticação Segura

Cada ERP usa o protocolo de autenticação nativo. Credenciais nunca trafegam em plain text — apenas tokens com expiração controlada.

// TOTVS — OAuth 2.0 POST /api/oauth2/v1/token grant_type=client_credentials client_id={app_id} client_secret={secret}
🔄

Sincronização Delta

Apenas os dados modificados são sincronizados — nunca toda a base. Isso reduz latência e consumo de banda, ideal para ERPs on-premise.

// Parâmetros de sincronização GET /api/products ?modifiedSince=2025-01-01T00:00:00Z &pageSize=100 &page=1
📦

Pedidos em Fila

Pedidos gerados offline entram em fila local (SQLite) e são enviados ao ERP assim que a conexão volta, com retry automático e log de erros.

// Payload de pedido { "origin": "rellav_app", "vendedor_id": "V001", "cliente_id": "C00123", "itens": [...], "offline_at": "2025-05-01T14:22:00Z" }
🪝

Webhooks em Tempo Real

Quando o ERP aprova ou rejeita um pedido, o app do vendedor é notificado em segundos via webhook — sem o vendedor precisar consultar.

// Evento de aprovação POST /rellav/webhook/pedido { "evento": "pedido.aprovado", "pedido_id": "PED-8821", "status_erp": "FATURADO" }
🌐

On-premise ou Nuvem

Funciona com ERPs instalados em servidores locais (via VPN ou túnel seguro) e também com ERPs 100% em nuvem sem configuração adicional.

// Configuração de endpoint { "host": "erp.suaempresa.com.br", "port": 8080, "tls": true, "timeout_ms": 10000 }
🛡️

Segurança e LGPD

Dados em trânsito com TLS 1.3. Dados em repouso com AES-256. Logs auditáveis por 90 dias. Conformidade total com a LGPD.

// Headers obrigatórios Authorization: Bearer {token} X-Rellav-Version: 2.0 X-Request-ID: {uuid} Content-Type: application/json

Dúvidas frequentes

Perguntas sobre integrações

As dúvidas mais comuns de gestores de TI e diretores comerciais antes de contratar o Rellav.

Preciso dar acesso ao banco de dados do meu ERP para integrar com o Rellav? ▾
Não. O Rellav usa exclusivamente a API oficial de cada ERP — nunca acessa diretamente o banco de dados. Isso garante que sua infraestrutura permaneça protegida e que todas as operações sigam as regras de negócio configuradas no seu ERP.
O que acontece com os pedidos se a internet cair durante a venda? ▾
O app funciona 100% offline. Os pedidos são gravados localmente no celular do vendedor com todos os dados (produto, quantidade, preço, cliente, localização). Assim que a conexão volta — seja Wi-Fi ou dados móveis — os pedidos são sincronizados automaticamente com o ERP na ordem correta, com timestamp do momento real da venda.
Meu ERP fica instalado em servidor interno da empresa (on-premise). Funciona? ▾
Sim. Para ERPs on-premise, usamos uma das duas abordagens: (1) abertura de porta específica no firewall da empresa com IP fixo autorizado, ou (2) instalação de um agente leve de sincronização dentro da rede interna que inicia conexão de saída — sem necessidade de abrir portas. A escolha depende da política de segurança da sua empresa.
O Rellav duplica pedidos no ERP se houver falha na sincronização? ▾
Não. Cada pedido tem um ID único gerado no app (UUID v4) que é enviado junto com o payload. Nosso sistema verifica se o pedido já existe no ERP antes de inserir. Em caso de timeout ou erro de rede, o sistema faz retry com o mesmo ID — e o ERP ignora a tentativa se o pedido já foi registrado. Duplicidade zero por design.
Posso ter múltiplos ERPs integrados ao mesmo tempo? ▾
Sim, isso é possível para empresas que operam com mais de uma unidade de negócio ou empresa CNPJ diferente. Cada unidade pode ter seu próprio conector de ERP configurado, e o vendedor seleciona de qual empresa está emitindo o pedido no momento da venda. Entre em contato para verificar a disponibilidade no seu plano.
Meu ERP não está na lista. O que faço? ▾
Nossa equipe faz integrações customizadas. Já desenvolvemos conectores para sistemas regionais, ERPs próprios e sistemas legados com API simples. O processo começa com um diagnóstico gratuito onde avaliamos a viabilidade técnica. Entre em contato via WhatsApp e descreva seu sistema — respondemos em até 24 horas úteis.
A integração afeta a performance do meu ERP? ▾
Não de forma significativa. O Rellav usa sincronização delta (apenas dados modificados) com controle de rate limit respeitando os limites da API de cada ERP. Para ERPs TOTVS com muitos acessos simultâneos, configuramos janelas de sincronização fora do horário de pico. O impacto médio observado em produção é inferior a 2% da carga normal do sistema.
